# GS3108T PRO 控制中心（Linux / Qt 6 Widgets / C++26）

这是给 GANSS GS3108T-PRO 键盘写的 Linux 配置工具。界面用 **Qt 6 Widgets** 手写绘制，
不依赖 QML；编译器使用 **Clang 21**，语言标准 **C++26**。

它直接通过 Linux 的 `/dev/hidraw*` 和键盘通信，不需要安装 Windows 驱动，
也不需要 Wine。

---

## 当前能做什么

| 功能 | 状态 |
|---|---|
| USB 有线灯效（模式 / 颜色 / 亮度 / 速度 / 方向 / 多彩） | 已验证 |
| 2.4G 无线灯效 | 已验证 |
| 我的专属配置（本地预设，一键应用） | 已支持 |
| TFT 时钟同步 | USB / 2.4G 都已验证 |
| TFT 动图（GIF / 静态图片） | USB 已验证 |
| 系统配置（响应时间 / 休眠 / 禁用 Win、ALT+F4、ALT+TAB） | USB 已验证 |
| 重置键盘 / 恢复出厂 | USB 已验证 |
| USB / 2.4G 接口自动识别 | 已支持 |
| 设备列表、连接方式切换、权限提示 | 已支持 |
| 用户灯光（逐键 RGB） | USB 已验证 |

> 结论先说：**灯效、校时、TFT 动图和系统配置已经能用**。系统配置和 TFT 动图目前只走 USB 有线；
> 2.4G 下灯光和校时正常，但驱动本身也不会往 2.4G 写系统设置或动图。
> Windows 驱动里还有逐键灯光、TFT 动图等模块，它们需要继续从
> `DeviceDriver.exe` 里把报文挖出来，不是 UI 层能凭空变出来的。
> 侧灯、音乐律动、宏和按键映射不在本项目的范围内。

## 编译环境

需要：

- Linux（Wayland 或 X11 都可以）
- CMake 3.30 或更新
- Clang 21（需要支持 `-std=c++26`）
- Qt 6.5 或更新：Core / Gui / Widgets / Svg
- make（预设使用 Unix Makefiles）

Debian / Ubuntu 可以这样装（按项目规范用 `pkexec`，不要用 `sudo`）：

```bash
pkexec apt-get install -y --no-install-recommends \
    clang cmake make qt6-base-dev qt6-svg-dev
```

确认版本：

```bash
clang++ --version     # 需要 21.x
cmake --version       # 需要 3.30+
qmake6 -query QT_VERSION
```

## 构建和运行

```bash
cd gs3108t-pro-linux-controller
cmake --preset clang-cxx26
cmake --build --preset clang-cxx26
./build-clang/gs3108t-pro
```

`CMakePresets.json` 已经把编译器固定为 `clang++`，构建目录是 `build-clang`。

```bash
cmake -S . -B build-clang \
    -DCMAKE_CXX_COMPILER=clang++ \
    -DCMAKE_BUILD_TYPE=Release
cmake --build build-clang -j
```

## 界面

左侧七个页面：

- **灯光控制**：模式网格、色轮、十六进制颜色、亮度、速度、方向、多彩。
  右下角固定一个「应用到键盘」按钮，滚动页面时也一直可见。
  页面底部是「我的专属配置」：把当前这整套参数存成一份预设，
  以后一键应用或删除。
- **用户灯光**：逐键 RGB。在键盘图上点选或拖框选键，用色轮 / HEX /
  常用颜色按钮设颜色，点「写入键盘」后键盘切到实时灯光模式并显示。
  支持新建、删除多组方案，方案保存在本机，切组会自动写回键盘；
  写入时只支持 USB 有线。按 `FN+(-)` / `FN+(+)` 会退出实时模式，
  回到键盘自己保存的灯效，再点一次「写入键盘」即可恢复。
- **TFT 时钟**：显示本机时间，点「同步当前时间」会把时间写进键盘屏幕的 RTC。
- **TFT 动图**：选择 GIF 或静态图片，程序会按 240×135 转成 RGB565 上传到键盘；
  动图最多 108 帧，超过会截断，单张图片按 1 帧处理。当前只支持 USB 有线，
  108 帧大约需要 4 分钟。
- **系统配置**：按键响应档位（1–5）、休眠时间（不休眠 / 1 / 5 / 30 分钟）、
  禁用 Win 键 / ALT+F4 / ALT+TAB。写入后立即生效，不需要再点保存。
  页面最下面是「重置键盘」和「恢复出厂」：前者清空用户灯光 / 自定义灯光数据，
  后者还会清逐键灯光，并把灯效和系统配置恢复默认。两个按钮都会先弹确认框。
  当前只支持 USB 有线；2.4G 下按钮会置灰并给出提示。
- **设备与连接**：显示检测到的配置接口、当前连接方式、udev 权限命令。
- **关于**：版本、协议摘要、功能进度。

灯效页的编号就是键盘固件的模式号，范围 1–20，已经**逐项实测校准**。
命名规律是「驱动语言文件（2052.lan）的字符串 ID − 520」，与键盘本体
`FN+8` / `FN+9` 循环时的显示顺序并不相同——那个顺序是固件菜单的排列，
两套编号不要互相换算。

| 编号 | 灯效 | 编号 | 灯效 |
|---|---|---|---|
| 1 | 静态恒亮 | 11 | 随波逐流 |
| 2 | 单点亮 | 12 | 峰回路转 |
| 3 | 单熄灭 | 13 | 一触即发 |
| 4 | 繁星点点 | 14 | 一石二鸟 |
| 5 | 漫天飞舞 | 15 | 涟漪扩散 |
| 6 | 百花争艳 | 16 | 川流不息 |
| 7 | 动态呼吸 | 17 | 重峦叠嶂 |
| 8 | 光谱循环 | 18 | 斜风细雨 |
| 9 | 彩泉涌动 | 19 | 来回穿梭 |
| 10 | 多彩纵横 | 20 | 关闭背光 |

选中一个编号后点「应用到键盘」即可预览。命令行的 `--modes` 能打印同一张表。

预设保存在 `~/.config/gs3108t-pro/presets.json`，纯人可读的 JSON，
可以直接备份、拷贝到别的机器，或手工编辑。文件不存在时界面显示空状态，
第一次点「保存当前设置」才会创建。

## 2.4G 怎么测

1. 按键盘上的 `FN+4` 切到 2.4G 模式（说明书里的模式切换键）。
2. 按一下键盘按键，解除休眠。
3. 先确认接口存在：

   ```bash
   ./build-clang/gs3108t-pro --list
   ```

   应该能看到 `usage 0xFF60`、`output 32` 的 `GS3108T-PRO 2.4G` 接口。

4. 先确认 2.4G 链路是通的。校时协议有回执，适合用来确认：

   ```bash
   ./build-clang/gs3108t-pro --clock-test --wireless
   ```

   如果键盘 TFT 时间更新了，说明 2.4G 通信正常；没反应就先检查 `FN+4` 和接口。

5. 发一个测试灯效：

   ```bash
   ./build-clang/gs3108t-pro --apply-test --wireless
   ```

6. 看键盘有没有变成红色呼吸。**回执/写入成功不等于灯真的变了**，一定要肉眼看。
6. 如果没反应，回到图形界面「设备与连接」页，把连接方式切到「2.4G 无线」，
   再回灯光页点应用；同时确认键盘已经被 `FN+4` 切到 2.4G。

> 2.4G 灯效的报文是从驱动反汇编里推出来的，目前还没有在真实 2.4G 连接下
> 由用户目视确认。USB 灯效和两种模式的校时都已经验证过。

## 权限（udev）

普通用户需要能读写 `/dev/hidraw*`。仓库里带了一份规则文件：

以下命令在项目根目录执行：

```bash
pkexec install -m 644 assets/70-gs3108t-pro.rules \
    /etc/udev/rules.d/70-gs3108t-pro.rules
pkexec udevadm control --reload-rules
pkexec udevadm trigger --subsystem-match=hidraw --action=change
```

验证：

```bash
getfacl /dev/hidrawN
```

应该能看到当前用户有 `rw-`。没有权限时，图形界面会显示失败原因，
设备页也会给出同样的命令。

## 协议摘要

完整说明在项目根目录的 `GS3108T-PRO-时间同步-协议与实现.md` 和
`HID设备驱动逆向方法论-交接文档.md`。

### USB 有线

- 接口：`usage page 0xFF13`，64 字节 Feature。
- 每次发送 65 字节（1 字节 report ID 0 + 64 字节数据）。
- 灯效序列：

  ```
  00 04 18                                    进入会话
  00 04 13 ... 第 9 字节 = 01                 准备
  00 mode R G B 00 00 00 00                  数据
     colorful brightness speed direction
     00 00 AA 55
  00 04 02                                    结束
  00 04 F0                                    保存
  ```

- 校时序列：`04 18` → `04 28` → 时间包 → `04 02`。
  时间包从 `00 01 5A 年 月 日 时 分 秒 00 星期` 开始，末尾 `AA 55`。

### 2.4G 无线

- 接口：`usage page 0xFF60`，32 字节 Output。
- 发送 33 字节（report ID 0 + 32 字节数据），第 32 字节是前 32 字节之和的低 8 位。
- 灯效帧：

  ```
  00 05 10 00 mode R G B 00 00 00 00
  colorful brightness speed direction 00 00 AA 55
  ... 00 校验和
  ```

- 校时帧：`00 0C 10 00 00 01 5A 年 月 日 时 分 秒 00 星期 ... AA 55 校验和`。

### 系统配置（仅 USB）

系统配置不是 `04 13` 灯效包，而是 `04 17` 准备 + 一个独立的 64 字节数据包：

```
00 04 18                                     进入会话
00 04 17 01 ... 第 9 字节 = 01               准备写配置
00 00 01 <alttab> <altf4> <win> 00 <sleep> 00 <resp> ... AA 55
00 04 02                                     结束（写入即生效，不需要 04 F0）
```

| 偏移 | 含义 | 取值 |
|---|---|---|
| `data[2]` | 禁用 ALT+TAB | 0 / 1 |
| `data[3]` | 禁用 ALT+F4 | 0 / 1 |
| `data[4]` | 禁用 Windows 键 | 0 / 1 |
| `data[6]` | 休眠时间 | 0 不休眠 / 1 一分钟 / 2 五分钟 / 3 三十分钟 |
| `data[8]` | 按键响应档位 | 1–5 |

注意：成功时 `04 02` 的回执第 5 个字节是 `01`；如果是 `FF`，说明固件拒收了这一包。
常见原因有两个：键盘还在 2.4G 模式，或者键盘已经休眠。先按一下键盘唤醒，
确认处于有线模式后重试即可。
`KeyboardController::sendSystemConfigUsb` 会把这个回执当作失败。

### 重置键盘 / 恢复出厂（仅 USB）

「重置键盘」是清空两组灯光数据：

```
04 18 → 04 11 data[8]=09 → 9 × 64 字节全零 → 04 02 → 04 F0
04 18 → 04 27 data[8]=09 → 9 × 64 字节全零 → 04 02 → 04 F0
```

「恢复出厂」在此基础上再多做三步：

```
04 19 → 04 15 data[8]=08 → 8 × 64 字节全零 → 04 02      清逐键灯光
04 18 → 04 13 data[8]=01 → 默认灯效 → 04 02 → 04 F0     模式 11（随波逐流）、颜色 FF0000、亮度 5、速度 3
04 18 → 04 17 … → 默认系统配置 → 04 02                  休眠 5 分钟、响应 2 档、禁用全关
```

注意：这些批量写入的 `04 02` 回执是 `FF`，驱动自己也不把它当失败，
所以重置流程只看 Feature 写入是否成功，不校验 `04 02` 的状态字节。

### TFT 动图（仅 USB）

动图/图片上传走两条通道：命令走 `0xFF13`（64 字节 Feature），数据走 `0xFF68`
（4096 字节 Output）。

```
00 04 18                                     进入会话
00 04 72 01 ... 第 9/10 字节 = 分块数        准备上传（data[2]=槽位 1，data[8..9] 小端）
  每个分块：写 4097 字节到 0xFF68            第 0 字节是 report ID 0，后 4KB 是数据
00 04 02                                     结束
```

上传内容是 256 字节头 + 帧数据：

| 偏移 | 含义 |
|---|---|
| 头[0] | 帧数（单张图片 = 1，最多 108） |
| 头[1..N] | 每帧延时 = GIF 延时(ms) / 2 |
| 头[N+1..255] | `0xFF` 填充 |
| 之后 | 每帧 240×135 个 RGB565 像素，小端 |

34 帧（约 2.2MB）大约 1–2 分钟；108 帧（约 7MB）大约 4 分钟。

### 用户灯光 / 逐键 RGB（仅 USB）

先把灯效切到实时灯光模式 `0x80`，再写 576 字节逐键数据：

```
04 18
04 13 data[8]=01
80 00 00 00 00 05 00 00 00 AA 55        模式 0x80，亮度 5
04 02
04 F0                                    保存模式
04 18
04 23 data[2]=00 data[8]=09              9 个 64 字节包
576 字节逐键数据
04 02
```

576 字节 = 144 条 4 字节记录，格式为 `[key_index][R][G][B]`。
`key_index` 来自官方驱动的 `rgb-keyboard.xml`，范围 1–124，没有灯的索引留 0。
最后两字节固定 `AA 55`，会覆盖第 143 条记录的 G/B 字节。

写入后键盘停在实时灯光模式；按 `FN+(-)` / `FN+(+)` 会退出该模式，
回到键盘自己保存的灯效，需要再点一次「写入键盘」恢复。
驱动也是同样的行为，不是持久化写入。

### 已验证的字段

- `mode` 取值 1–20，与驱动语言文件里的灯效名称一一对应（`语言 ID − 520`），
  完整表格见 `src/lightmodes.h`。
- RGB 顺序是 R、G、B（发 `FF0000` 得到红色）。
- `data[8]` 是多**彩**开关：光谱循环这类模式不受颜色影响，但随波逐流等
  单色可用的模式在多彩关闭时才会用 `data[1:4]` 的颜色。
- `data[9]` 是亮度（5 = 高亮）。
- `data[10]` 是速度，`data[11]` 是方向；
  这几个字段的顺序是从驱动结构体偏移推出来的，如果发现某个参数没效果，
  可以在 `LightPage` 里调整；本地逆向目录里的 `gskbd-light.py` 支持
  `--params` 直接试（该脚本不随仓库分发）。

1. ~~校准灯效模式~~（已完成）：1–20 全部与名称对上，见 `src/lightmodes.h`。

5. ~~用户灯光（逐键 RGB）~~（已完成）：实时灯光模式 `0x80` + `04 23` 写 576 字节，
